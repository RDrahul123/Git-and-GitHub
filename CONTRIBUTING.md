# Contributing

Thank you for helping improve these learning notes. Contributions may clarify an explanation, correct a command, improve accessibility, add practice, or fix a broken link.

## Before you begin

1. Search existing issues and pull requests to avoid duplicate work.
2. For a large change, open an issue first to discuss scope.
3. Fork the repository (if needed), create a focused branch, and edit the relevant Markdown file.

## Documentation standards

- Write for a beginner first, then add technical depth.
- Use short paragraphs, descriptive headings, and GitHub-compatible relative links.
- Test commands in a disposable repository; show representative output and label output that varies by version.
- Prefer Mermaid/ASCII diagrams and include useful alt text for any image.
- Explain dangerous operations and safer options near the command.
- Keep examples consistent with current Git behavior and avoid publishing credentials or personal information.
- Add navigation links and a quick recap to new module pages.

## Validate your change

- Preview the Markdown on GitHub or in a GitHub-compatible renderer.
- Check relative links, code fences, table alignment, and Mermaid syntax.
- For command examples, confirm they are safe and reproducible in a temporary repository.
- Describe any checks you ran in the pull request.

## Pull request process

Use a clear title such as `docs: clarify reset modes`. Explain why the change helps, summarize what changed, and list validation performed. Keep one concern per pull request when practical. Reviewers may suggest revisions to preserve accuracy and consistency.

## Code of conduct

Be respectful, constructive, and welcoming. Critique ideas and text, not people. Harassment and discriminatory behavior are not acceptable.
